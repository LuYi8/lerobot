扩量采集（一条命令：备份旧数据集→更新集数→采集→stats重算→同步train/actor json）
bash gym-hil/collect_demo.sh 120
参数：[采集集数] [record配置json]，默认 60 集 + gym-hil/record_hil_env.json
注意：gym-hil/dataset 已存在时直接跑上面的 record 命令会 FileExistsError
     （LeRobotDataset.create 不覆盖不追加，mkdir(exist_ok=False)）；脚本自动把旧数据
     备份为 dataset_backup_<时间戳>；采集环节需人工键盘遥操作；采集中断可手动 mv 恢复；
     采集完成后脚本自动重算 stats（写回 meta/stats.json）并同步 dataset_stats 到
     train_hil_env.json / actor_hil_env.json，同时校验 offline_buffer_capacity >= 数据集帧数

合并数据集（把旧备份追加进新采集的数据集；上游 aggregate_datasets 合并+自动重算 stats）
bash gym-hil/merge_demo.sh [新数据集] [旧数据集] [输出目录] [train json] [actor json]
默认：新=gym-hil/dataset，旧=最新 gym-hil/dataset_backup_<时间戳>，输出=gym-hil/dataset_merged
流程：校验→合并（视频重新打包，几分钟~十几分钟）→校验集数=两源之和→同步 dataset_stats
注意：合并后总帧数增加，offline_buffer_capacity 需 >= 总帧数（脚本会校验并告警）；
     源数据集只读不被修改，替换前随时可重来

直接运行（典型流程）：
# 1) 若上次采集被 Ctrl+C 中断（数据不完整，如只有几集空转），先删除不完整数据集（确认备份完好后再执行）：
rm -rf gym-hil/dataset
# 2) 把最新备份合并进新采集的数据集（输出 gym-hil/dataset_merged）：
bash gym-hil/merge_demo.sh
# 3) 确认合并结果（脚本打印集数/帧数）后替换：
rm -rf gym-hil/dataset && mv gym-hil/dataset_merged gym-hil/dataset

【critic 加 GRU 实验（方案2，critic_use_recurrent，2026-08-14 蓝图已定稿未实施）】
开关：--algorithm.critic_use_recurrent true（默认 false，与 use_recurrent 相互独立、自由组合）
      全关=上游逐位一致 / 仅 actor=现有 R-SAC / 仅 critic=消融 / 双关=目标实验
设计：GRU 输入=纯观测（obs_enc），动作在 Q 头前拼入（head 输入 256+4）；
      done 掩码镜像 actor（pred 用 done、target 用左移 1 位的 done_next）；
      critic 仅 learner 侧生效（actor 不构造 critic）。
配套：--algorithm.sequence_length 8（同 R-SAC；B = batch_size//T，每批帧数 64 不变）
      --algorithm.use_torch_compile false（torch.compile 包 critic，critic GRU 首次进
      dynamo 有 TracingShapeError 风险；4 条实验命令统一关闭，消融对比不含 compile 混杂因素）
数据管线（决策 7 修订，2026-08-14）：--policy.offline_buffer_capacity 8500 --policy.online_buffer_capacity 4000
      （离线 8500 为装下 8252 帧演示的硬约束——from_lerobot_dataset 容量不足直接 ValueError；
      总帧数 12500、内存较当前 +25%；纯 SAC / R-SAC 基线必须同配置重跑，99% 历史基线仅参考）
详见 gym-hil/上下文归档_SAC增加GRU方案2_critic.md 第 5 节（命令全集）与 §8 待办。
